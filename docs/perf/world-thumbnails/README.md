# Automatic Earth world thumbnails

Released build 58 (`4cd96bf`) was reproduced in a newly created disposable Earth world. After terrain settled, vanilla reported zero rendered sections while Earth had 809 visible near meshes, no pending near meshes and 26,948 far ranges. No icon.png was created. Returning to the real world-selection screen showed its fallback image: one entry and zero custom icons. Two older disposable Earth worlds also lacked icons; two vanilla controls had them.

Vanilla only captures a world icon after more than ten rendered sections and its existing all-sections-ready check. Earth renders actual cubic terrain separately from those empty carrier sections. The fix substitutes actual cubic readiness for the section-count check only when a cubic world is active. Visible near meshes must exceed ten with no pending near meshes; a far-only view must have more than ten ranges and 100% visible refinement. Ordinary worlds call the original section count. Vanilla retains its other readiness check, one-second retries, pre-GUI framebuffer capture, center crop, 64×64 resize, asynchronous PNG write and existing-file protection.

The exact source `e67cf90bda4b86c3977da5250f49238161b2be1b` passed verifyShimArtifact with the actual stock Photon ZIP: 158 tests, 154 passed, four optional skips, zero failures/errors. Three new pure readiness tests cover empty/building views, ready near terrain and far-only refinement. The JAR SHA-256 is recorded in measurements.json.

Native checks used the Mac built-in Retina display, OpenGL 4.1 Metal 91.7, Sodium 0.8.13 and Iris 1.8.14-beta.1. Fresh Earth worlds with shaders off and stock Photon on both produced real automatic 64×64 icons. After normal save-and-exit, the actual filtered WorldSelectionList entry loaded each icon; its DynamicTexture matched all 4,096 RGBA pixels of the PNG on disk. Screenshots of both world lists and their icons were visually inspected. Reopening the shader-free world preserved its existing icon SHA-256. A newly created ordinary vanilla world on the patched build produced and displayed its icon through the original readiness path, also matching all 4,096 pixels.

The local test fixture invoked normal create-world, screen and disconnect APIs; it did not write or force a world icon. This is native automatic-capture and actual world-list evidence, not a mouse-only UI test. Raw screenshots, logs, test worlds and the local driver stay outside the repository. Test-driver periodic far-status queries in vanilla worlds logged expected fixture-only null errors; the icon and world-list probes succeeded. Personal worlds and installations were not used.
