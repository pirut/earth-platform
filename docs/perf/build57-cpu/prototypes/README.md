# Exact-output prototypes and cross-vendor gates

The **current build (0.1.0-alpha.57)** automatically uses bounded exact client run meshing and local performance logs. Players install one normal-version JAR with no switches. Shadow hints, direct server run generation/transport, command caching, water depth batching and stricter upload pacing remain **off by default**. No graphics quality, distance, simulation radius, fade or texture setting is reduced. PR #93 remains draft and unmerged. The main [report](../README.md) retains the earlier build-57 measurements; those FPS numbers do not describe these prototypes.

## Shadow blocker hints

`-Dearthplatform.far.shadowHints=true` enables two ping-pong R32F hint textures. Each stores a successful original `earth_sun` sample index plus one, with zero meaning no hint. A hint is never a cached shadow answer. The candidate uses the current reconstructed position, camera projection, sun, noise and depth sampler. It repeats the original float multiplication sequence, current positive-W and inclusive [0,1] UV reachability checks, and the unchanged original thickness predicate. Nonfinite/invalid values, clipping or a failed blocker test fall back to the original loop. AO, RG8 shadow output and subsequent history/filtering remain unchanged.

Why skipping prior depth fetches preserves the binary result: if the proposed current blocker passes and no preceding original clipping check terminates the ray, the original loop either finds an earlier blocker (also returning 1.0) or reaches this blocker and returns 1.0. Otherwise the original loop runs. The stored index is a successful original-loop sample; it need not remain the *first* blocker after edits. The CPU oracle exercises every hint/termination index and varied blocker patterns. This proof does not replace driver-specific floating-point/output tests.

Sampling and output attachments are distinct. The write texture is detached before roles swap. Resize invalidates the read history. Unsupported shader/FBO setup uses the original pass. Extra hint VRAM is capped at **32 MiB** across both textures; 1708x960 needs 12.51 MiB. Larger unsupported sizes, including 3840x2160 under this cap, retain the original full-quality pass. No vendor, warp size, unified-memory or discrete-memory assumption selects the feature.

### Actual M4 Pro shader evidence

The standalone `ShadowGpuOracle.java` compiles the exact production GLSL, renders disposable synthetic depth fields, and compares original/hinted shadow **and AO raw float bits**, before normalized RG8 storage. It passed **96 cases / 2,672,688 channels / zero mismatches**, with **308,456 validated fast-hint hits**. Cases vary depth/camera-like motion, edit-like ridges, sun direction/night, sky/fade-like gaps, jittered projection, stale/malformed hints and resize. A diagnostic extra output confirms the fast branch was exercised. This is a bounded GPU fixture, not exhaustive world, mod or vendor coverage.

At 1708x960 with production RG8 shadow and R32F hint targets, two same-context ABBA blocks used 24 asynchronous elapsed-query samples per window. No result was read before availability; no glFinish or readback occurred inside measured scopes. The mean GPU pass duration was **0.6500 ms original versus 0.7751 ms hinted (+19.25%, worse)**; 96 samples per path, maximum result age eight submitted frames, zero dropped samples. Window means were 0.629–0.669 ms original and 0.758–0.783 ms hinted. These are GPU component durations, not FPS or independent multi-launch confidence intervals. This result **fails the benefit gate**, so the experiment remains off. Live world movement/edit/sun/fade/resize benefit is not established.

The Mac exposes OpenGL 4.1 Metal 91.7 / ARB_timer_query, but reports **timestamp counter bits=0, elapsed counter bits=32**. The instrumentation therefore prefers timestamp pairs when supported and otherwise uses non-nested TIME_ELAPSED, skipping occupied targets. Availability, age, wrap ambiguity, ownership loss and bounded storage are checked. No blocking query result retrieval is used. Native timestamp mode still needs verification on another implementation.

## Exact far surface packets

`-Dearthplatform.far.surfacePackets=true` prototypes generation of exact vertical material runs for levels 3–8 without vertical strata or rasterized giants. Fine far levels, giant rasterization and strata retain the dense generator. Level-3 canopy and wider ground foliage, discrete water/ice, bedrock cover, fractional drops and biome palette defaults are retained. Near generation and simulation are unchanged.

The immutable base holds flat run words plus per-column offsets, exact registry state IDs, original biome quart samples/default and drops. Sparse block exceptions produce a new revisioned immutable overlay; stale/non-increasing revisions fail. An overlay above 16,384 entries requires dense fallback. Bounds limit rows, runs and experimental encoded bytes. The compact experimental codec uses explicit bounded integers and preserves state properties and unsigned drops. It is **not an existing network or save format**; no saved IDs, network IDs or personal world data changed.

`SurfaceGenerator.surfacePacket()` is the direct bounded API and returns null for unsupported cases. The opt-in `farColumn()` integration deliberately **materializes the existing sections before the original edit/network/meshing boundary**. Saved-cube downsampling, water/air edit rules, build summaries, halo/normal calculations, packed faces and their ordering still use that boundary. The packet field is the immutable generated base; the sections remain authoritative after legacy edits. The sparse-overlay API is tested, but is not a replacement for that existing edit fold.

The current build consumes runs **directly in the client mesher**. For eligible coarse levels, it snapshots the authoritative received sections into exact immutable runs once, then enumerates conservative exposed-voxel candidates in the original row/z/x order. It skips only fully hidden opaque interior voxels; the original face emission/merging and packed ordering remain. Borders, all water, and neighbours of air/water expanded for unequal drops are retained. Vertically varying biomes, coverage masks, smooth terrain, excessive runs/heights and conversion uncertainty use the original dense mesher. No retained second column cache is added. Existing sections/network/edit handling remain authoritative, so edits are reflected in each new immutable snapshot.

**Direct packet transport, production server edit-overlay plumbing and end-to-end streaming/refinement/memory gains remain unfinished and inactive.** The developer-only generation adapter can cost more than dense generation. A smaller experimental encoding is not an enabled FPS, VRAM, upload or network improvement.

### CPU exactness and component scope

The dense generator remains an independent enumeration oracle. Tests passed:

- 90 bounded columns / **860,160 voxels**, exact states, biomes, drops and every legacy encoded section byte, before and after experimental codec roundtrip.
- Original fallback comparisons for fine levels, giants and strata; canopy, snow, water, ice, negative coordinates and material boundaries in bounded fixtures.
- The **actual packed CPU mesher**: 12 masked/unmasked jobs, **14,555 packed quads and 12 water meshes**, exact ordering/counts/normals/halo and declared vertex attributes. Synthetic stable looks avoid requiring a model manager. Uninitialized BLOCK padding byte 31 is excluded; separate native real-model/format audits are recorded below. Converted-input, differing neighbour biomes/bottoms/drops, edited dense fallback and conservative candidate omissions have independent dense-oracle comparisons.
- Sparse cave-air, overhang/log and water exceptions, revision rejection/revert, immutable input ownership, unsigned drops and resource/decoder bounds. Additional varied registry-state/property and compact-codec checks are tracked by CI/local final verification.

The clean Mac component suite (source `921cf635`, before the current-build packaging-only change) measured conversion **plus complete meshing**, against an independent original dense build. At level 3, settled rounds took 1.776–1.779 ms versus 2.271–2.349 ms dense; level 5 took 0.691–0.754 ms versus 1.017–1.138 ms; level 8 took 0.384–0.403 ms versus 0.748–0.756 ms. Java allocation at level 8 rose from 423,296 to 435,144 bytes/job (about 12 KiB); level 5 rose from 989,656 to 1,001,504 bytes/job. These are synthetic in-memory components, **not whole-game FPS or streaming gains**. Warm-up drift is visible, especially level 3.

The inactive direct generator measured roughly 50–51 us versus 103–105 us dense at level 5, and 46–47 us versus 95–98 us at level 8. Its compact encoding was 2,674/2,819/2,754 bytes at levels 3/5/8, versus 8,293/4,148/4,146 legacy bytes. Encoding, decoding and materialization can be slower: level 8 run encode/decode/materialize were 15.8/36.0/85.0 us versus legacy encode/decode 4.0/13.3 us. Revisioned edit snapshots were about 0.7 us. First-touch observations are not fresh cold JVM/disk/download trials; no end-to-end load, refinement, streaming or universal memory gain is claimed.

## Completed native Mac controls

One fresh disposable client launch at 1708x960, render/simulation 12, Sharpest reach (~94 km), cap 260 and vsync off repeated the command-cache problem in four 60-second windows. Cache off: **47.10/47.01 FPS, p95 37.43/37.45 ms, p99 38.85/38.99 ms, >40 ms 0.106/0.142%**. Cache on: **49.96/49.71 FPS, p95 39.69/39.66 ms, p99 40.17/40.30 ms, >40 ms 1.868/1.777%**. The two off windows each contained one >100 ms frame; on windows contained none. Geometry, selection/allocation versions and queues were stable within each window. This is a single-launch control, not the full three-launch correction acceptance gate. The cache remains off.

Full-rate native GPU observation cost about 1.25% FPS (29.50 off versus 29.11–29.16 on), with p95 rising roughly 35.2 to 37.5 ms in that Photon scene. Current diagnostics sample only one frame in 120. Full-rate sampled far-opaque GPU duration averaged 26.98–27.03 ms, sun+occlusion 0.561–0.562 ms, water colour ~0.354 ms; result age was at most two frames. These pass scopes do not measure complete frame/presentation time and must not be added as an FPS prediction.

Live hint off/on/on/off 30-second windows were 29.21/29.13/29.05/29.10 FPS. Hints showed no whole-game gain; one on window had p99 40.62 ms and >40 ms 1.03%, versus off p99 38.12/38.18 ms and ~0.11%. This does not support enablement.

Real-model, original/cached-coverage live output matched declared geometry/attributes/order: shader-free **24 jobs / 13,240 quads / 59 water parts**, Photon **24 jobs / 20,650 quads / 68 water parts**. Uninitialized vertex padding differences are separately counted rather than asserted equal. Underwater entry/exit, near/far transitions and Photon screenshots were reviewed; these are bounded fixture checks, not universal pixel identity. Disposable test terrain intentionally contains water roofs/walls. Current-default source `a037c24` also matched the independent dense mesher in 24-job shader-free/near/Photon audits, including masked dense fallbacks. A targeted follow-up checked **24 eligible automatic-run jobs per shader mode**, levels 3–8, **16,889 quads / 59 water parts** each, with all 24 actually using runs. Declared attributes, order, look tables and geometry match; raw uninitialized padding is counted separately. Reviewed current screenshots retain near/far/water structure in the bounded disposable fixture.

The same current-default JAR observed **46.714 FPS, p95 37.232 / p99 38.862 ms** without shaders, and **29.577 FPS, p95 35.533 / p99 37.238 ms** with Photon in separate settled 30-second windows. >40 ms frequencies were 0.143% and 0.902%; no >100 ms frame occurred in either window. These are smoke observations, **not matched evidence of a whole-game speedup**; scene/time and system memory pressure prevent that comparison. The logger captured 62 windows (~165 KiB), 125,871 used conversions, zero recorded error events, zero log drops and zero query drops.

The independent Astra/high review requested changes in `a037c24`; all were fixed and cleared on exact source `dbf8f2d`. Sparse neighbour overlays now participate in exact height queries; the independent dense oracle materializes all packet neighbours. The new packed-neighbour test failed before the fix and passes after it. Converted dense cave-air, overhang/log-axis, persistent-leaf, partial-water levels 0–7 and dropped-column fixtures compare exact packed output. Every rotated diagnostic file repeats the bounded build/GPU header, including its UTF-8 bytes in the cap; a tiny-cap test crosses more than three rotations. Generation errors count outside console throttling; shader errors count once. A separate native oracle produced three invalid shader compiles and exactly three recorded shader errors, plus five immediately recorded generation events.

Exact rebuilt JAR `dbf8f2d` received a separate 15-second native menu startup/log-header smoke and exited cleanly. Its SHA-256 is `4a87800057623a040e99b1645a28f9da4fc59a91e7fd33607da367e80e7507df`. ## Cross-vendor validation matrix

| Target | Java/CPU exactness | GLSL compiler/output | Native GPU timings | Live quality/performance |
| --- | --- | --- | --- | --- |
| Apple M4 Pro, macOS / GL 4.1 | Local exactness/current-build suite passed | Actual driver: 96 raw-output cases passed | Non-nested elapsed mode measured; timestamp bits zero | Completed controls/quality checks above; no whole-game run-mesher gain claimed |
| NVIDIA discrete GPU, Windows/Linux | Portable Java implementation; Linux x86 CI covers CPU logic, not NVIDIA hardware | NVIDIA driver compilation/output **not verified** | Timestamp/elapsed selection and occupied-target behavior need hardware test | **Not tested; no access used** |
| AMD discrete GPU, Windows/Linux | Same CPU/CI scope | AMD driver compilation/output **not verified** | Same capability and ownership gates need hardware test | **Not tested; no access used** |
| Generic GLSL 330 reference compiler | Not a hardware test | glslang 16.6.0 linked both original and hinted GLSL 330 passes | Not applicable | Not applicable |

Dedicated-GPU considerations: hints add texture reads, an MRT write, FBO work and divergent ray-validation branches; reduced depth fetches do not guarantee a gain. The VRAM cap avoids unbounded extra allocation. No coherent CPU/GPU memory, persistent mapping, subgroup width, vendor extension or Apple-only fast path is assumed. The client run mesher emits the same packed GPU faces and uploads; it has **no demonstrated discrete-VRAM/upload saving**. Any future direct transport must preserve ordering and avoid turning compression into many small PCIe uploads. Hardware acceptance requires each vendor's driver, representative dedicated VRAM sizes, stationary/moving/edit/sun/fade/resize cases, p95/p99 and stutters, GPU result ages/drops and observer-off/on controls. Do not extrapolate the Mac result in either direction. The offline, unauthorized Windows machine was not used.

## Reproduction

Use JDK 21 and the separately installed inputs from [BUILDING.md](../../../BUILDING.md). Run the full suite, including the actual Photon ZIP test where available. `EARTH_SURFACE_BENCH=1` opts into `FarSurfacePacketBench`; serialize it outside client/performance windows. Logs beginning `SURFACE_COMPONENT`, `SURFACE_PACKET_ORACLE` and `SURFACE_MESH_ORACLE` describe scope and counts.

For the standalone GPU oracle, compile this directory's `ShadowGpuOracle.java` with the repository's `FarLodShaders.java`, `GlShaders.java`, `GpuQueryRing.java`, `diagnostics/BuildInfo.java` and `diagnostics/PerfFailures.java`, using the installed LWJGL 3.3.3 and JOML jars plus platform native jars on the classpath. Run `io.earthplatform.minecraft.cubic.client.ShadowGpuOracle`; on macOS add `-XstartOnFirstThread`. Pass `bench` for the asynchronous GPU component test and optionally `-Dearthplatform.oracle.csv=/path/results.csv`. It requires a working primary monitor/context, changes no worlds or shader packs, and uses synchronous readback only in the **correctness** phase/warm-up. Never run it alongside Minecraft, builds or CPU benchmarks.

The official macOS-universal reference validator archive SHA-256 was `89b2f56d6f202f45ae0f5c0fc04ee2a23e7deb8ac38db36907a6c2b6447efcaa`; version 16.6.0 successfully linked `sun.vert` with each production original/hinted fragment shader using `glslang -l` (OpenGL GLSL 330). This verifies reference-language/link validity, not another vendor’s driver.

The adjacent `ShaderFailureCountOracle.java` uses the same standalone classpath to check actual invalid-compile event counts in a disposable GL context; it reads no game/world data.

The [Khronos glslang project](https://github.com/KhronosGroup/glslang) supplies a separate portable GLSL reference validator; a successful reference compile does not verify an NVIDIA or AMD driver. The standalone oracle and all CPU tests are original code in this repository. External compiler binaries, game assets, shader packs, raw worlds and private logs are not committed.
